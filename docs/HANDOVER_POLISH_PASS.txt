3. WHAT CHANGED, AND WHY
------------------------

3.1 TOP NAVIGATION - show every page, no "N more" menu           (tabs/ui.py)
    Change: the page row now shows all pages and scrolls sideways when they do not fit.
            Links snap to the left edge so none is left half cut off. The row is given a
            minimum width so the IT admin's four pages fit on a laptop screen.
    Why:    Streamlit hides pages behind a "2 more" popover when the row is crowded. The
            user did not like the hidden pages.
    How:    CSS override of Streamlit's own "rc-overflow" markup (opacity, position and
            display of its items; scroll snap; flex and min-width on the nav).
    Tried and removed: a fade/arrow hint and then a grey shadow at the right edge to show
            that the row scrolls. The user found both unattractive, so they were removed.
            Nothing now signals that the row scrolls; at normal laptop widths every page
            fits so it is not needed.
    Caveat: this depends on Streamlit's internal element names (data-testid="stTopNav" and
            the rc-overflow classes). A Streamlit upgrade could break it. The app is
            pinned to streamlit==1.66.1.

3.2 NARROW SCREENS - the ">>" button did nothing                  (tabs/ui.py)
    Change: the sidebar is now hidden only while the top navigation is showing.
            The sidebar (which holds the page list on narrow screens) gets top padding so
            the Role / Stories / Help bar does not cover the first link.
    Why:    below a certain width Streamlit moves the page links into a sidebar. The app's
            CSS hid the sidebar at ALL widths, so the ">>" opener had nothing to open.
    Verified: at 500 px wide the button opens Home / New request / Requests and a link
            navigates.

3.3 FINANCE DETAILS - (i) hover note                              (tabs/tab_intake.py, tabs/ui.py)
    Change: an (i) icon sits at the right end of the "Finance details: credit, terms and
            banking" bar. Hovering (or tabbing to) it shows: "These are private. They are
            needed before the request can be sent." If none of the finance fields are
            required it says "These are private. They are optional here."
            The old always-visible caption inside the section was removed.
    Why:    requested wording, shown only on hover to keep the form short.
    Note:   the old caption also said "Each person only sees what their role needs". That
            sentence no longer appears anywhere.
    How:    pure CSS tooltip; the (i) is placed over the expander header with a keyed
            container (finance_box).

3.4 HOME - tiles                                                  (tabs/ui.py, tabs/tab_home.py)
    Change: tile contents are centred; the number is bold and coloured; each tile is a
            white card with a coloured bar on top and a soft shadow (was a fully tinted
            pastel box with a coloured border). Rows with fewer than three tiles keep the
            tile width of a three-tile row (they no longer stretch). An empty tile says
            "Nothing here". Tiles lift slightly on hover.
    Why:    the user thought the tinted boxes looked unprofessional. The cause was the thin
            light-weight number plus alert-banner-style colouring. White cards with an
            accent are the usual dashboard look.
    Known cosmetic issue: a tile with the extra "N over 2 days" line and "Only the late
            ones" button is taller than its neighbours. An attempt to equalise heights did
            not work and was reverted (it also faded the top bars).

3.5 HOME - rest of the page                                       (tabs/tab_home.py)
    - "Next step" button for "See waiting times" is now the calm outline style (it did not
      need action).
    - "Recent activity" rows are two lines (title and status pill, then date and
      who-did-what) instead of one crowded line.

3.6 REQUESTS PAGE                                                 (tabs/tab_inbox.py, tabs/common.py)
    - Each request card starts collapsed under "Details, history and email". It opens by
      itself when the viewer must decide it, or when only one request is listed.
      Why: the full table on every card made the list hard to scan.
    - In the details table the technical status row (U_ReqStatus) is hidden (the status is
      already a pill above) and U_Requester is shown as "Requested by" with a plain name.
      Why: SAP field names looked unfinished next to normal fields.
    - The "Over N days only" checkbox sits closer to the filter tabs.
    - Toast wording (see 3.12).

3.7 AUDIT TRAIL                                                   (tabs/tab_audit.py, tabs/ui.py)
    Change: the table on screen now shows dates as "25 Oct 2026, 16:50", roles as "IT
            admin" and "System", statuses by their plain names, and the Detail column as a
            sentence (for example "Switched from Requestor to IT admin") instead of raw
            JSON. The table is laid out for a wider page, so rows are shorter.
    Why:    this is the page a reviewer opens to judge trust, and raw JSON, microsecond
            timestamps and codes such as IT_ADMIN looked unfinished.
    Safety: the stored audit entries, the hash chain, the filters and the CSV download are
            unchanged. The CSV still has the raw stored values. Only the on-screen table
            is reworded.
    Caveat: row height is still set by the longest cell, so rows are taller than ideal.
    Code:   tab_audit.py has audit_frame(audit_log, config=None) (words when a config is
            passed, raw when not) and detail_text(); ui.table now accepts page_px.

3.11 NEW DEMO REQUEST THAT HAS ALREADY WAITED 3 DAYS             (data/demo_seed.json, tabs/demo_data.py)

6. HOW TO UNDO THIS PASS
------------------------

The backup is the project as it was just before this pass (it still has the earlier
features). To restore on macOS, from the folder that holds both:

  rsync -a --delete --exclude .venv --exclude .git \
        lives-mdm-platform_BACKUP_before_polish/ lives-mdm-platform/

There is no git history, so copy the current folder somewhere first. Then run pytest -q and
python tools/check_config.py. To undo only one item, the sections above name the file and
the rule to revert (most are a few CSS lines in tabs/ui.py).
