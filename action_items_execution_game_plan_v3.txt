--------------------------------------------------------------------------------
WHAT CHANGED IN v3
--------------------------------------------------------------------------------
Question that drove v3: "how does the system know which NUHS to follow, and can we
confirm it deterministically (no AI) from other fields such as GST number, address or
contact person, treating a match as representative when 2-3 fields align?"
1. EVIDENCE QUORUM replaces the v2 weighted sum. CONFIRMED needs 2+ DISTINCT field
   groups to agree, at least one of them non-weak. Country and customer group alone
   can never confirm (hundreds of customers share them). One strong signal alone (for
   example a matching email domain) is UNCONFIRMED and the requester is asked.
2. SIX NEW SIGNALS: TAX_ID_NEAR_MATCH (one-typo tax ID), GST_REG_MATCH, POSTAL_CODE_MATCH,
   ADDRESS_SIMILAR, CONTACT_PERSON_MATCH, PHONE_MATCH. They use new OPTIONAL CUSTOMER
   fields (OCRD): U_GSTRegNo, Address, ZipCode, CntctPrsn, Phone1. Existing scenario
   payloads stay valid because the fields are optional.
3. "WHICH NUHS" ANSWERED IN THREE LAYERS: every approved expansion is scored; evidence
   picks a winner when one leads by ambiguity_win_margin groups; a tie goes to the
   requester, never to a guess. alias_map entries are now UNIONED with initialisms
   generated from the master, so ambiguity is detected even if nobody listed it
   (v2 let alias_map shadow master-derived initialisms).
4. EVIDENCE DISCLOSURE (privacy fix): evidence compares against an existing customer's
   contact person, phone and address. Only MDM Lead and Auditor see compared values;
   every other role sees signal labels only; the audit log stores signal IDs, not values.
5. NEW SCENARIO 3 VARIANTS: 3f (postal code + contact person, free email), 3g (tax ID
   typo), 3h (one strong signal alone), plus a "which NUHS" two-expansion fixture.
6. DEDUP BENCHMARK: tests/test_dedup_benchmark.py reports precision and recall on a
   labelled pair file, for the Executive Summary.
7. SECTION 7 gains a CUT LINE (MUST / SHOULD / COULD) for the 5-day schedule.
8. The companion prompt file is re-synced: v2 prompts still said _dup_override and
   had no tiers, corroboration functions or new fields.

--------------------------------------------------------------------------------
WHAT CHANGED IN v2
--------------------------------------------------------------------------------
1. ROLE SWITCH + FIELD-LEVEL SECURITY (new). One app, one dataset, eight personas.
   Each persona sees different tabs, different rows and different field values.
   Bank account numbers are fully visible ONLY to the Payments Officer, and only
   after approval. Enforcement lives in a new module, engine_security.py.
2. ABBREVIATION RESOLVER (new). Explicit alias catch before fuzzy scoring:
   NUHS -> National University Hospital Singapore,
   SMU Solutions -> Singapore Management University Solutions.
   Also handles dotted initialisms (N.U.H.S.), token abbreviations
   (Nat. Uni. Hosp.) and auto-generated initialisms from existing master names.
3. Scenario 2 customer renamed "Sheng Siong Hospital Solutions" -> "SMU Solutions".
4. Dedup scoring fixed. v1 scored "Nat. Uni. Hospital Singapore" vs
   "National University Hospital" at ~60% (below its own 70% threshold) and
   scored "National University of Singapore" vs the hospital at ~99% (false
   positive). v2 adds abbreviation expansion, discriminator-word penalties and a
   core-token conflict cap. Scenario expectations are now computed, not hardcoded.
5. Validator now enforces enums and min_len (v1 defined them but never checked).
6. Routing conditions are structured data (no eval() of strings in JSON).
7. SLA engine reads rules from config, uses a pending_since clock (not
   last_updated_at) and accepts an injectable "now" for the 18-day simulator.
8. Scenario payloads corrected so each is valid except for its one intended defect.
9. Churn formula corrected (monthly average vs monthly average, baseline excludes
   the recent window). Cross-sell now covers A or B without C, with confidence/lift.
10. Mock data is GENERATED by a seeded script, not hand-written by an LLM.
11. Interface contracts (Section 6) and an execution timeline (Section 7) added.
12. EVIDENCE CORROBORATION (rev 2). A name/abbreviation match is no longer trusted on
    its own. Deterministic non-name evidence (email domain, country, customer group,
    alias token in the email domain) classifies each abbreviation-derived match as
    CONFIRMED, UNCONFIRMED, CONTRADICTED or AMBIGUOUS_ALIAS, and each tier has a
    different action. Missing evidence never auto-clears a match.
13. Routing flag renamed _dup_override -> _dup_review (it now also covers matches that
    need MDM confirmation, not only justified overrides).

================================================================================
PROJECT OVERVIEW & CORE DESIGN PRINCIPLES
================================================================================
Python + Streamlit prototype of the Lives Group MDM Orchestration & Regional
Analytics Engine.

CRITICAL TECHNICAL REQUIREMENTS:
1. NO HARDCODED RULES: field schemas, validation rules, regexes, thresholds,
   alias dictionaries, routing matrix, SLA timings, role permissions, field
   security policies, forecast and churn parameters ALL live in config_rules.json.
   Functions contain no business literals.
2. SAP BUSINESS ONE ALIGNMENT: models and payloads use SAP B1 table and field
   names (OCRD Business Partners, OITM Items, OOCR Cost Centers).
3. EXAMPLE SCENARIOS TAB: one-click scenarios for Appendix B & C (Amy, Wei Jie,
   Priya, Marcus, 18-day delay), each runnable under the correct persona.
4. ROLE-BASED VIEWS: a sidebar role switch changes what the SAME app shows.
   Security is enforced in a single module on the data, not by hiding widgets.
5. OUTLOOK / M365: Adaptive Card (Actionable Message) generator, webhook
   receiver contract, SLA escalation, email digest template (simulated in the
   prototype; contracts match a real deployment).
6. ABBREVIATION-AWARE MATCHING: alias catch runs before fuzzy scoring.
7. EVIDENCE QUORUM: a name match is only trusted when independent non-name fields
   (tax ID, GST, email domain, postal code / address, contact person, phone, country,
   group) agree: 2+ distinct field groups, at least one of them non-weak. Deterministic,
   config-driven, no AI at runtime.

SYSTEM DATAFLOW:
[Persona / Role Switch] --> [Dynamic Intake Form (config-driven)]
        |                              |
        |                              v
        |                  [Config-Driven Validation]
        |                              |
        |                              v
        |        [Abbreviation Resolver] -> [Fuzzy Dedup + Exact Tax-ID check]
        |                              |  -> [Evidence Quorum -> tier]  (Pass / Confirm / Justified Override)
        |                              v
        |                  [Structured Routing Matrix + State Machine]
        |                              |
        v                              v
[engine_security: row + field filter] <-- [Request Store (session) + Audit Log]
        |                              |
        v                              v
[Tabs: Inbox / Staging / SLA Board]   [M365 Adaptive Card + SLA Escalation]
                                       |
                                       v
[SAP B1 Staging (OCRD/OITM/OOCR)] --> [Engine 2: Cleansing -> Holt-Winters /
                                        Churn Radar / Cross-sell -> Regional View]

RULE: every value shown in the UI, exported, put in an Adaptive Card or written
to the audit log passes through engine_security.apply_field_security().

--------------------------------------------------------------------------------
2.1 CONFIG-DRIVEN VALIDATION (engine_mdm.py)
--------------------------------------------------------------------------------
Fixes vs v1: enums and min_len are now enforced; messages come from config;
empty optional fields skip format checks; numeric parsing is safe.

```python
import re

def _is_empty(v):
    return v is None or str(v).strip() == ""

def validate_against_config(domain, payload, config):
    dom = config["domains"].get(domain)
    if not dom:
        return False, ["Invalid domain specified."]
    msg, errors = config["messages"], []
    for f in dom["fields"]:
        key, label, val = f["field"], f["label"], payload.get(f["field"])
        empty = _is_empty(val)
        ctx = {"label": label, "field": key}

        if f.get("required") and empty:
            errors.append(msg["required"].format(**ctx)); continue
        for dep, targets in f.get("required_if", {}).items():
            if payload.get(dep) in targets and empty:
                errors.append(msg["required_if"].format(dep_field=dep, dep_value=payload.get(dep), **ctx))
        if empty:
            continue

        ftype = f.get("type", "string")
        if ftype == "float":
            try:
                num = float(val)
            except (TypeError, ValueError):
                errors.append(msg["not_number"].format(**ctx)); continue
            if "min" in f and num < f["min"]:
                errors.append(msg["min_value"].format(min=f["min"], **ctx))
        if ftype == "enum" and str(val) not in [str(o) for o in f["options"]]:
            errors.append(msg["invalid_option"].format(options=f["options"], **ctx))
        if "min_len" in f and len(str(val).strip()) < f["min_len"]:
            errors.append(msg["min_len"].format(min_len=f["min_len"], **ctx))
        if "regex" in f and not re.fullmatch(f["regex"], str(val)):
            errors.append(msg["invalid_format"].format(**ctx))
    return len(errors) == 0, errors
```

--------------------------------------------------------------------------------
2.2 ABBREVIATION RESOLVER + FUZZY DEDUPLICATION (engine_mdm.py)
--------------------------------------------------------------------------------
PIPELINE (per candidate vs each existing record of the same table / card_type):
  0. EXACT CHECK: any field in exact_match_fields (e.g. LicTradNum) equal ->
     match_basis EXACT_TAX_ID, score 100, hard block (no override).
  1. CLEAN: lowercase; collapse dotted initialisms (N.U.H.S. -> nuhs); strip
     punctuation; split into tokens.
  2. ABBREVIATION CATCH (explicit):
     a. alias_map: a token such as NUHS or SMU expands to its full name
        (NUHS -> national university hospital singapore;
         SMU Solutions -> singapore management university solutions).
        A list with several expansions = ambiguous alias; every expansion is
        scored and the best one wins, all are shown to the reviewer.
     b. token_map: Nat./Uni./Univ./Hosp./Mgmt./Solns. -> full word.
     c. dynamic_initialisms: initials of every existing master name are
        auto-registered as aliases (National University Hospital Singapore ->
        NUHS and NUH), so acronyms not yet in alias_map are still caught. These are
        UNIONED with any alias_map entry for the same key (v3): if the master holds both
        a hospital and a health system whose initials are NUHS, the ambiguity is
        detected without anyone listing it.
  3. NORMALIZE: drop legal-suffix words (pte, ltd, sdn, bhd...) and stop words.
     Do NOT drop meaningful words such as hospital / university / singapore
     (v1 dropped them, which destroyed the signal).
  4. SCORE: composite = 0.6 * token_set_ratio + 0.4 * Jaro-Winkler (weights from
     config), then:
     - DISCRIMINATOR PENALTY: if the candidate and the existing name differ in
       their set of discriminator words (hospital vs university, solutions vs
       none), subtract discriminator_penalty. This separates "National
       University Hospital" from "National University of Singapore", and
       "SMU Solutions" from "Singapore Management University".
     - CORE CONFLICT CAP: remove discriminator and geo words; if the remaining
       core tokens overlap (Jaccard) below core_min_jaccard, cap the score at
       core_conflict_cap. Separates "Singapore General Hospital" from
       "Singapore Eye Hospital".
  5. FLAG if composite >= similarity_threshold. Return match_basis =
     EXACT_<field> | ALIAS_EXPANDED | FUZZY, the alias hits, the resolved
     candidate name and a plain-English explanation for the UI.
  6. CORROBORATE (Section 2.2b): for abbreviation-derived matches, check non-name
     fields (tax ID typo, GST, email domain, postal code / address, contact person,
     phone, country, group). 2+ independent field groups must agree, at least one
     non-weak, to reach CONFIRMED; otherwise UNCONFIRMED / CONTRADICTED /
     AMBIGUOUS_ALIAS. The tier, not the name score alone, decides what happens next.

Reference implementation (prototype-tested on the pairs in the table below):

```python
import re, itertools
from rapidfuzz import fuzz, distance

def _tokens(text):
    s = str(text).lower()
    s = re.sub(r"\b(?:[a-z]\.){2,}", lambda m: m.group(0).replace(".", ""), s)  # N.U.H.S. -> nuhs
    s = re.sub(r"[^a-z0-9\s]", " ", s)
    return s.split()

def _drop(words, ab):
    skip = set(ab["legal_suffix_words"]) | set(ab["stop_words"])
    return [w for w in words if w not in skip]

def build_dynamic_aliases(existing_names, ab):
    out = {}
    if not ab.get("dynamic_initialisms"):
        return out
    geo = set(ab["geo_words"])
    for name in existing_names:
        words = _drop(_tokens(name), ab)
        for ini in {"".join(w[0] for w in words), "".join(w[0] for w in words if w not in geo)}:
            if len(ini) >= ab["initialism_min_len"]:
                out.setdefault(ini, set()).add(" ".join(words))
    return {k: sorted(v) for k, v in out.items()}

def resolve_name(text, ab, dynamic_aliases=None):
    """Return (variants, hits). variants = list of token lists with abbreviations expanded."""
    alias_map = {k.lower(): [v.lower() for v in vs] for k, vs in ab["alias_map"].items()}
    token_map = {k.lower(): v.lower() for k, v in ab["token_map"].items()}
    dyn = dynamic_aliases or {}
    options, hits = [], []
    for t in _tokens(text):
        if t in alias_map or t in dyn:
            # UNION of curated aliases and initialisms generated from the master (v3), normalised so
            # "national university of singapore" and "national university singapore" count as one.
            exp = list(dict.fromkeys(" ".join(_drop(_tokens(v), ab)) for v in alias_map.get(t, []) + dyn.get(t, [])))
            options.append(exp)
            hits.append({"token": t, "expands_to": exp, "source": "ALIAS_MAP" if t in alias_map else "AUTO_INITIALISM"})
        elif t in token_map:
            options.append([token_map[t]]); hits.append({"token": t, "expands_to": [token_map[t]], "source": "TOKEN_MAP"})
        else:
            options.append([t])
    variants = []
    for combo in itertools.islice(itertools.product(*options), ab["max_variants"]):
        variants.append(_drop([w for phrase in combo for w in phrase.split()], ab))
    return variants, hits

def _score(cand_words, exist_words, dd, ab):
    a, b = " ".join(cand_words), " ".join(exist_words)
    ts = fuzz.token_set_ratio(a, b) / 100.0
    jw = distance.JaroWinkler.similarity(a, b)
    w = dd["weights"]
    comp, penalty, capped = w["token_set"] * ts + w["jaro_winkler"] * jw, 0.0, False
    disc = set(ab["discriminator_words"])
    if {x for x in cand_words if x in disc} ^ {x for x in exist_words if x in disc}:
        penalty = ab["discriminator_penalty"]; comp -= penalty
    skip = disc | set(ab["geo_words"])
    ca, cb = {x for x in cand_words if x not in skip}, {x for x in exist_words if x not in skip}
    if ca and cb and len(ca & cb) / len(ca | cb) < ab["core_min_jaccard"]:
        comp, capped = min(comp, ab["core_conflict_cap"]), True
    return max(comp, 0.0), ts, jw, penalty, capped

def check_fuzzy_duplicates(domain, payload, existing_records, config):
    dom = config["domains"][domain]
    dd = config["deduplication_rules"][dom["sap_table"]]
    ab, field, key = dd["abbreviation_resolution"], dd["compare_field"], dom["key_field"]
    pool = [r for r in existing_records
            if "card_type" not in dom or not dd.get("match_same_card_type_only") or r.get("CardType") == dom["card_type"]]
    matches = []

    for ef in dd.get("exact_match_fields", []):                       # step 0
        if payload.get(ef):
            for r in pool:
                if str(r.get(ef, "")).strip().upper() == str(payload[ef]).strip().upper():
                    matches.append({"sap_id": r.get(key), "existing_name": r.get(field), "match_basis": "EXACT_" + ef,
                                    "confidence_score": 100.0, "hard_block": dd["exact_match_policy"] == "HARD_BLOCK", "tier": "EXACT_ID",
                                    "explanation": f"{ef} is identical to existing record {r.get(key)}."})
    cand_raw = payload.get(field, "")
    if not cand_raw or not ab.get("enabled", True):
        return matches
    dyn = build_dynamic_aliases([r.get(field, "") for r in pool], ab)
    cand_variants, hits = resolve_name(cand_raw, ab, dyn)

    for r in pool:
        exist_words = resolve_name(r.get(field, ""), {**ab, "alias_map": {}, "token_map": {}})[0][0]
        best = max(((_score(cv, exist_words, dd, ab), cv) for cv in cand_variants), key=lambda x: x[0][0])
        (comp, ts, jw, pen, capped), cv = best
        if comp >= dd["similarity_threshold"]:
            expanded = bool(hits) and " ".join(cv) != " ".join(_drop(_tokens(cand_raw), ab))
            matches.append({
                "sap_id": r.get(key), "existing_name": r.get(field),
                "resolved_candidate_name": " ".join(cv),
                "match_basis": "ALIAS_EXPANDED" if expanded else "FUZZY",
                "alias_hits": hits, "token_set": round(ts, 3), "jaro_winkler": round(jw, 3),
                "discriminator_penalty": pen, "core_conflict_capped": capped,
                "confidence_score": round(comp * 100, 1), "hard_block": False,
                "explanation": (f"'{cand_raw}' resolves to '{' '.join(cv)}' and matches existing record "
                                f"{r.get(key)} '{r.get(field)}' at {round(comp * 100, 1)}%.")})
    ranked = sorted(matches, key=lambda m: m["confidence_score"], reverse=True)
    return assign_tiers(ranked, payload, {r.get(key): r for r in pool}, hits, dd)   # Section 2.2b
```

--------------------------------------------------------------------------------
2.2b EVIDENCE QUORUM (engine_mdm.py)  [rev 2; upgraded to a multi-field quorum in v3]
--------------------------------------------------------------------------------
PROBLEM: a name or abbreviation says what an organisation MIGHT be called, not which
organisation THIS requester means. "NUHS" can denote the hospital or the health system;
two different hospitals can have near-identical names. A name match alone is weak evidence.

SOLUTION (no AI at runtime, no hardcoding): after the name score passes the threshold, look
at fields that have nothing to do with the name. A match is trusted only when several
INDEPENDENT fields agree (the "2 to 3 fields aligned" rule). Every number, field and rule
below lives in config.deduplication_rules.OCRD.corroboration.

HOW THE SYSTEM KNOWS WHICH "NUHS" TO FOLLOW (three layers, in this order):
  1. EXPANSIONS: every approved expansion of the abbreviation is tried (alias_map entries
     are UNIONED with initialisms generated from the master names, so a master that holds
     both a hospital and a health system with initials NUHS is detected as ambiguous
     without anyone listing it). Each expansion is scored against the master by name.
  2. EVIDENCE: each candidate record is scored on non-name fields. If exactly one is
     CONFIRMED, or one leads the next by ambiguity_win_margin agreeing groups, it wins and
     the others become SUPERSEDED (listed as alternatives only).
  3. HUMAN: if it is still a tie, the requester is asked to pick the organisation they
     mean (AMBIGUOUS_ALIAS) and MDM reviews. The system never guesses between ties.

SIGNALS (config values; demo configuration shown). Missing data on either side never fires.
  Group           Signal                   Strength  What it checks
  --------------  -----------------------  --------  ----------------------------------------
  TAX_ID          TAX_ID_NEAR_MATCH        STRONG    Tax/UEN differs from the existing record
                                                     by ONE typo (one edit or one swap). An
                                                     identical ID is already a hard block.
  TAX_ID          GST_REG_MATCH            STRONG    U_GSTRegNo equal after removing
                                                     punctuation and case
  EMAIL           EMAIL_DOMAIN_MATCH       STRONG    requester email domain equals or is a
                                                     sub-domain of the existing record's
                                                     (free-mail domains such as gmail.com ignored)
  EMAIL           EMAIL_DOMAIN_HAS_ALIAS   MEDIUM    the abbreviation the requester typed
                                                     (e.g. nuhs) appears in their email domain
  LOCATION        POSTAL_CODE_MATCH        MEDIUM    ZipCode equal after removing spaces/case
  LOCATION        ADDRESS_SIMILAR          MEDIUM    street address >= 0.85 similar after
                                                     expanding Rd/St/Ave/Blk (needs 3+ words)
  CONTACT_PERSON  CONTACT_PERSON_MATCH     MEDIUM    contact person >= 0.85 similar, word order
                                                     and titles (Mr/Dr...) ignored (needs 2+ words)
  PHONE           PHONE_MATCH              MEDIUM    last 8 digits equal (country code ignored)
  COUNTRY         SAME_COUNTRY             WEAK      U_Country equal
  CUSTOMER_GROUP  SAME_CUSTOMER_GROUP      WEAK      GroupCode equal
  (conflict)      DIFFERENT_COUNTRY        CONFLICT  U_Country present on both and different
  weight is kept only for display and tie-break ranking; the tier comes from the quorum.

QUORUM RULE (config.corroboration.quorum):
  Count DISTINCT GROUPS that fired. Two signals in one group count once (postal code +
  street address is one fact; email domain + abbreviation-in-domain is one fact).
  CONFIRMED     agreeing groups >= 2 AND at least 1 of them non-weak (MEDIUM or STRONG)
  CONTRADICTED  at least 1 conflict AND no non-weak group agrees
  UNCONFIRMED   everything else, including missing data (fail safe)
  WHY "at least one non-weak": country and customer group are shared by hundreds of
  customers (Singapore + hospital). Two weak fields agreeing proves nothing, so they can
  support a match but never carry it alone.
  WHY one strong signal alone is not enough: a corporate email domain can be shared by
  sister companies, and a requester may sit in a related entity. One strong signal alone is
  UNCONFIRMED and the requester is asked.
  A DIFFERENT tax ID is deliberately NOT a contradiction: a duplicate typed with a wrong
  tax ID is exactly the case this engine must catch. An IDENTICAL tax ID is a hard block
  (Section 2.2 step 0). An identical GST number is only corroboration, never a block,
  because one GST registration can legitimately cover several group entities.
  Plain fuzzy matches (match_basis FUZZY, no abbreviation involved) are not corroborated;
  they take config.default_tier_otherwise (CONFIRMED).

ACTION BY TIER (config.tiers; the UI reads action and ui_message from config):
  EXACT_ID         HARD_BLOCK              cannot submit; use the existing record
  CONFIRMED        BLOCK_UNLESS_JUSTIFIED  blocking dialog, justification required,
                                           request routed to MDM Lead (R01)
  UNCONFIRMED      REQUESTER_MUST_CONFIRM  requester answers "same organisation" (stop,
                                           use existing) or "different organisation"
                                           (state why); either way routed to MDM Lead
                                           (R01) with the answer attached
  CONTRADICTED     WARN_ONLY               informational note, no routing change
  AMBIGUOUS_ALIAS  REQUESTER_MUST_CHOOSE   requester picks the intended organisation;
                                           the pick is re-scored and re-tiered
  SUPERSEDED       NONE                    listed as an alternative only
  The requester's answer and the signal IDs that fired are written to the audit log
  (DUPLICATE_REQUESTER_ANSWER). dup_review_required(matches, config, domain) tells the
  intake flow whether to set _dup_review before routing.

SAFETY PRINCIPLES
  - Missing evidence never clears a match; it lands in UNCONFIRMED for human review.
  - Corroboration can lower confidence in a match but never silently delete it:
    CONTRADICTED matches are still displayed.
  - EVIDENCE DISCLOSURE: the evidence compares against an EXISTING customer's contact
    person, phone, address and email, which a Requester may not be entitled to see.
    evidence_for_role() returns signal labels only (e.g. "Same contact person") to every
    role except config.corroboration.detail_visible_roles (MDM Lead, Auditor), who also see
    the compared values. The audit log stores signal IDs and the tier, never the values.
  - Evidence is only as good as the master data. The SAP master seed must carry E_Mail,
    U_Country and GroupCode on existing customers, and Address, ZipCode, CntctPrsn, Phone1,
    U_GSTRegNo wherever they are known. Empty fields simply do not fire.
  - Priya's decisions are the ground truth for later tuning (weights, thresholds, quorum,
    alias_map); change config, not code.

```python
import re
from rapidfuzz import fuzz, distance

STRENGTH = {"WEAK": 0, "MEDIUM": 1, "STRONG": 2}     # CONFLICT signals are handled separately

def _domain(email):
    e = str(email or "")
    return e.split("@")[-1].strip().lower() if "@" in e else ""

def _domains_related(a, b):
    return bool(a and b) and (a == b or a.endswith("." + b) or b.endswith("." + a))

def _alnum(v):
    return re.sub(r"[^A-Za-z0-9]", "", str(v or "")).upper()

def _digits(v):
    return re.sub(r"\D", "", str(v or ""))

def _addr_words(text, tm):
    s = re.sub(r"[^\w\s]", " ", str(text or "").lower())
    return [tm["address_token_map"].get(w, w) for w in s.split()]

def _person_words(text, tm):
    s = re.sub(r"[^\w\s]", " ", str(text or "").lower())
    return [w for w in s.split() if w not in set(tm["person_title_words"])]

def _signal_hit(s, payload, existing, alias_tokens, cc):
    """Return (fired, detail). Missing data on either side never fires."""
    kind, tm, free = s["kind"], cc["text_match"], set(cc["free_email_domains"])
    a, b = payload.get(s.get("candidate_field")), existing.get(s.get("existing_field"))
    if kind == "email_domain_contains_alias_token":
        da = _domain(a)
        return (bool(da) and da not in free and any(t in da for t in alias_tokens)), da or "-"
    if kind == "email_domain_match":
        da, db = _domain(a), _domain(b)
        return (da not in free and db not in free and _domains_related(da, db)), f"{da or '-'} vs {db or '-'}"
    if a in (None, "") or b in (None, ""):
        return False, "-"
    detail = f"{a} vs {b}"
    if kind == "field_equal":
        same = (_alnum(a) == _alnum(b)) if s.get("normalize") == "alnum_upper" else (str(a) == str(b))
        return same, detail
    if kind == "field_different":
        return str(a) != str(b), detail
    if kind == "near_match":             # typo-level difference only; identical IDs are the step-0 hard block
        na, nb = _alnum(a), _alnum(b)
        d = distance.DamerauLevenshtein.distance(na, nb)
        return (0 < d <= tm["tax_id_max_edit_distance"] and min(len(na), len(nb)) >= tm["tax_id_min_len"]), detail
    if kind == "text_similar":
        wa, wb = _addr_words(a, tm), _addr_words(b, tm)
        if min(len(wa), len(wb)) < tm["address_min_tokens"]:
            return False, detail
        return fuzz.token_sort_ratio(" ".join(wa), " ".join(wb)) / 100.0 >= tm["address_min_similarity"], detail
    if kind == "person_similar":
        wa, wb = _person_words(a, tm), _person_words(b, tm)
        if min(len(wa), len(wb)) < tm["person_min_tokens"]:
            return False, detail
        return fuzz.token_sort_ratio(" ".join(wa), " ".join(wb)) / 100.0 >= tm["person_min_similarity"], detail
    if kind == "phone_match":
        da, db, n = _digits(a), _digits(b), tm["phone_compare_last_digits"]
        return (len(da) >= n and len(db) >= n and da[-n:] == db[-n:]), detail
    return False, detail

def corroborate(payload, existing, alias_tokens, cc):
    """Deterministic non-name evidence, resolved by the quorum rule in config."""
    q, fired, conflicts, score = cc["quorum"], [], [], 0.0
    for s in cc["signals"]:
        hit, detail = _signal_hit(s, payload, existing, alias_tokens, cc)
        if not hit:
            continue
        rec = {"id": s["id"], "label": s["label"], "group": s["group"], "strength": s["strength"],
               "weight": s["weight"], "detail": detail}
        score += s["weight"]
        (conflicts if s["strength"] == "CONFLICT" else fired).append(rec)
    groups = {r["group"] for r in fired}
    non_weak = {r["group"] for r in fired if STRENGTH[r["strength"]] >= 1}
    if len(groups) >= q["min_agreeing_groups"] and len(non_weak) >= q["min_non_weak_groups"]:
        tier = "CONFIRMED"
    elif len(conflicts) >= q["contradiction_min_conflicts"] and not non_weak:
        tier = "CONTRADICTED"
    else:
        tier = "UNCONFIRMED"
    return {"score": round(score, 2), "signals": fired, "conflicts": conflicts,
            "agreeing_count": len(groups), "non_weak_count": len(non_weak), "tier": tier}

def assign_tiers(matches, payload, pool_by_id, hits, dd):
    """Adds tier + corroboration to each match, then resolves ambiguous aliases."""
    cc = dd.get("corroboration", {})
    if not cc.get("enabled"):
        return matches
    alias_tokens = [h["token"] for h in hits if h["source"] in ("ALIAS_MAP", "AUTO_INITIALISM") and len(h["token"]) >= 3]
    for m in matches:
        if m.get("hard_block"):
            m["tier"] = "EXACT_ID"; continue
        if m["match_basis"] in cc["apply_to_match_basis"]:
            m["corroboration"] = corroborate(payload, pool_by_id[m["sap_id"]], alias_tokens, cc)
            m["tier"] = m["corroboration"]["tier"]
        else:
            m["tier"] = cc["default_tier_otherwise"]
    alias_matches = [m for m in matches if m.get("match_basis") == "ALIAS_EXPANDED"]
    ambiguous = any(len(h["expands_to"]) > 1 for h in hits)
    if ambiguous and len({m["sap_id"] for m in alias_matches}) > 1:
        confirmed = sorted((m for m in alias_matches if m["tier"] == "CONFIRMED"),
                           key=lambda m: (m["corroboration"]["agreeing_count"], m["corroboration"]["score"]), reverse=True)
        margin, winner = cc["quorum"]["ambiguity_win_margin"], None
        if len(confirmed) == 1:
            winner = confirmed[0]
        elif len(confirmed) > 1 and (confirmed[0]["corroboration"]["agreeing_count"]
                                     - confirmed[1]["corroboration"]["agreeing_count"]) >= margin:
            winner = confirmed[0]
        for m in alias_matches:
            if winner is None:
                m["tier"] = "AMBIGUOUS_ALIAS"
            elif m is not winner:
                m["tier"] = "SUPERSEDED"
    return matches

def dup_review_required(matches, config, domain):
    tiers = config["deduplication_rules"][config["domains"][domain]["sap_table"]]["corroboration"]["tiers"]
    return any(tiers[m["tier"]]["requires_mdm_review"] for m in matches)

def evidence_for_role(corroboration, role, cc):
    """What a given role may see of the evidence: labels for everyone, compared values only for privileged roles."""
    full = role in cc["detail_visible_roles"]
    out = []
    for r in (corroboration or {}).get("signals", []) + (corroboration or {}).get("conflicts", []):
        item = {"id": r["id"], "label": r["label"], "strength": r["strength"]}
        if full:
            item["detail"] = r["detail"]
        out.append(item)
    return out
```

2.3 STRUCTURED ROUTING MATRIX & STATE MACHINE (engine_mdm.py)

No eval(). Conditions are data; the engine interprets them. First rule by
priority whose condition is true wins; the matched rule id is written to the
audit log ("routed by R03").

```python
OPS = {
    "eq": lambda a, b: a == b, "ne": lambda a, b: a != b,
    "gt": lambda a, b: a is not None and float(a) > b, "gte": lambda a, b: a is not None and float(a) >= b,
    "lt": lambda a, b: a is not None and float(a) < b, "lte": lambda a, b: a is not None and float(a) <= b,
    "in": lambda a, b: a in b, "not_in": lambda a, b: a not in b,
}

def _leaf(c, ctx):
    return OPS[c["op"]](ctx.get(c["field"]), c["value"])

def _eval(cond, ctx):
    ok_all = all(_leaf(c, ctx) for c in cond.get("all", []))
    any_list = cond.get("any")
    ok_any = True if not any_list else any(_leaf(c, ctx) for c in any_list)
    return ok_all and ok_any

def route_request(domain, payload, config, dup_review=False):
    ctx = {**payload, "_domain": domain, "_dup_review": dup_review}
    for rule in sorted(config["routing_matrix"], key=lambda r: r["priority"]):
        if _eval(rule["condition"], ctx):
            return {"route_to": rule["route_to"], "approver_role": rule["approver_role"], "rule_id": rule["id"]}
    raise ValueError("No routing rule matched; routing_matrix must end with a catch-all rule.")
```
State machine: transitions and allowed actor roles come from config.state_machine.
transition(request, action, user, config, comment=None) must reject an action if
the user's role is not allowed for that state, append to request["history"], set
pending_since ONLY when entering a pending state (not on every edit), and write

DESIGN RULES
  R1. Deny by default: unknown fields get security.default_policy (HIDDEN).
  R2. One chokepoint: apply_field_security() is the only function that returns
      record values for display, export, cards, digests or audit. Code that
      touches raw records for display is a bug.
  R3. Most-restrictive wins: effective policy = min(role policy, channel cap).
      Ranking FULL(2) > MASKED(1) > HIDDEN(0). Channel EMAIL caps BANK_DETAILS at
      HIDDEN, so even Payments never receives full bank numbers by email or card.
  R4. State-aware policy: Payments sees full bank details only after the request
      is APPROVED (need-to-know follows the workflow).
  R5. Row scope is enforced before field policy: a Regulatory Officer never even
      sees a Finance request exist. Supervisor gets meta_fields only.
  R6. Write-only entry: BANK_DETAILS inputs render as password-style fields and
      are never echoed back to the requester after submit.
  R7. Every FULL view of BANK_DETAILS writes SENSITIVE_FIELD_VIEWED_FULL to the
      audit log. Role switches are logged too (ROLE_SWITCHED).
  R8. No st.json(raw_record) or st.dataframe(raw_df) anywhere. Cached functions
      must include the role in their cache key.

```python
RANK = {"FULL": 2, "MASKED": 1, "HIDDEN": 0}

def _resolve(entry, role, status):
    e = entry.get(role, entry.get("*", "HIDDEN"))
    if isinstance(e, dict):
        return e["policy"] if status in e["only_in_states"] else e["otherwise"]
    return e

def _mask(value, style_name, sec):
    st = sec["mask_styles"][style_name]
    s = str(value)
    if "keep" in st:
        return st["mask_char"] * max(len(s) - st["keep"], 0) + s[-st["keep"]:]
    return st["text"]

def apply_field_security(record, domain, role, config, status=None, channel="APP"):
    sec = config["security"]
    status = status or record.get("U_ReqStatus") or record.get("status")
    fields = {f["field"]: f for f in config["domains"][domain]["fields"]}
    view, report = {}, {}
    for key, val in record.items():
        f = fields.get(key)
        if f is None:
            policy = "FULL" if key in sec["system_fields_visible"] else sec["default_policy"]
            cls = "GENERAL"
        else:
            cls = f.get("security_class", "GENERAL")
            policy = _resolve(sec["classes"][cls]["policy_by_role"], role, status)
        cap = sec["channel_caps"].get(channel, {}).get(cls)
        if cap and RANK[cap] < RANK[policy]:
            policy = cap
        report[key] = policy
        if policy == "FULL":
            view[key] = val
        elif policy == "MASKED":
            view[key] = _mask(val, sec["classes"][cls].get("mask_style", "redact"), sec)
    return view, report   # report feeds the audit log and the Security Lens
```

SLA ESCALATION ENGINE (config-driven, injectable clock):

```python
from datetime import datetime, timezone

def process_sla_escalations(requests_db, config, now=None):
    now = now or datetime.now(timezone.utc)
    sla, out = config["sla"], []
    for req in requests_db:
        if req["status"] not in sla["watched_states"]:
            continue
        hours = (now - datetime.fromisoformat(req["pending_since"])).total_seconds() / 3600.0
        for rule in sorted(sla["rules"], key=lambda r: r["after_hours"]):
            flag = f"sla_{rule['id']}_done"
            if hours >= rule["after_hours"] and not req.get(flag):
                req[flag] = True
                out.append(_build_sla_action(rule, req, config, now))
    return out
```
_build_sla_action resolves recipients from config (current approver, supervisor,
delegate), fills subject/title templates, and for AUTO_REASSIGN_TO_DELEGATE
changes current_approver_email to config.delegates[role] and restarts nothing
else. pending_since must be timezone-aware ISO-8601; it is set only when a request
enters a pending state, so edits and comments do not reset the SLA clock.

Streamlit cannot run a true background scheduler (especially on Community
Cloud), so the prototype exposes a simulated clock (sim_now) and calls
process_sla_escalations(db, config, now=sim_now) when the slider moves. State in
the README that production uses Azure Functions / Power Automate on a timer.

4.2 NOISE CLEANING (engine_analytics.py)

```python
import pandas as pd

def clean_transaction_data(raw_df, config):
    nf = config["analytics"]["noise_filter"]
    df = raw_df[(raw_df["RecordType"] == nf["record_type"]) &
                (raw_df["U_ReqStatus"].isin(nf["status_in"]))].copy()
    df["DocDate"] = pd.to_datetime(df["DocDate"])
    df["YearMonth"] = df["DocDate"].dt.to_period("M").dt.to_timestamp()   # month start, DatetimeIndex-friendly
    return df
```

--------------------------------------------------------------------------------
4.3 HOLT-WINTERS FORECAST (engine_analytics.py)
--------------------------------------------------------------------------------
Signature: generate_demand_forecast(clean_df, entity, country, product_line, config)
-> DataFrame[period, actual, fitted, forecast, method_used]. Filters by entity,
country and product line (v1 ignored entity).

```python
from statsmodels.tsa.holtwinters import ExponentialSmoothing
import numpy as np, pandas as pd

def _series(clean_df, entity, country, product_line):
    s = (clean_df[(clean_df["U_Entity"] == entity) & (clean_df["U_Country"] == country) &
                  (clean_df["U_ProductLine"] == product_line)]
         .groupby("YearMonth")["Quantity"].sum().astype(float))
    if s.empty:
        return s
    full = pd.date_range(s.index.min(), s.index.max(), freq="MS")
    return s.reindex(full, fill_value=0.0)

def generate_demand_forecast(clean_df, entity, country, product_line, config):
    fc = config["analytics"]["forecast"]
    s, h = _series(clean_df, entity, country, product_line), fc["horizon_months"]
    if len(s) < fc["min_points_trend"]:
        return pd.DataFrame()          # caller shows "not enough history"
    use_seasonal = len(s) >= fc["min_points_seasonal"]
    try:
        model = ExponentialSmoothing(s, trend=fc["trend"],
                                     seasonal=fc["seasonal"] if use_seasonal else None,
                                     seasonal_periods=fc["seasonal_periods"] if use_seasonal else None).fit()
        method = "HOLT_WINTERS_ADDITIVE" if use_seasonal else "HOLT_LINEAR_TREND"
    except Exception:
        model = ExponentialSmoothing(s, trend=fc["trend"]).fit(); method = "HOLT_LINEAR_TREND_FALLBACK"
    fut = model.forecast(h).clip(lower=fc["clip_min"])
    hist = pd.DataFrame({"period": s.index, "actual": s.values, "fitted": model.fittedvalues.values})
    new = pd.DataFrame({"period": fut.index, "forecast": fut.values})
    out = pd.concat([hist, new], ignore_index=True); out["method_used"] = method
    return out
```
Additive seasonality with seasonal_periods=12 needs two full cycles, so 24 months
is the minimum; the code falls back and labels the method used on the chart.

--------------------------------------------------------------------------------
4.4 CHURN RADAR & CROSS-SELL
--------------------------------------------------------------------------------
CHURN (calculate_churn_radar(clean_df, config, as_of=None)):
  - recent window = last 3 complete months. Baseline = the 12 months immediately
    BEFORE the recent window (so the baseline is not diluted by the decline).
  - Compare monthly averages:
      Delta = (avg_monthly_3M - avg_monthly_baseline) / avg_monthly_baseline
  - Flag when Delta < -0.20. Skip customers with fewer than 15 months of history
    or baseline average below min_baseline_monthly_volume (lumpy small accounts).
  - Output: CardCode, CardName, U_Entity, U_Country, baseline_avg, recent_avg, delta,
    risk_band. Show only to roles whose analytics scope is ACCOUNT_LEVEL; AUDITOR
    sees aggregate counts only; roles with NONE do not see the tab.
CROSS-SELL (calculate_cross_sell_opportunities(clean_df, config, as_of=None)):
  - Accounts that purchased any antecedent product (A or B) in the window but no
    consequent product (C) within window_days (90).
  - Also return rule statistics across all accounts: support, confidence
    P(C within 90d | A or B) and lift, so "conversion probability" is a measured
    number, broken down by entity (SPD, QTS, QTG).
Error handling: empty inputs, missing months (reindexed to zero), small samples
and zero baselines return empty frames or labelled results, never exceptions.
