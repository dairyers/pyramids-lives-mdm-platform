--------------------------------------------------------------------------------
- RE-SYNCED WITH SPEC v3. The v2 prompts still described the pre-corroboration flow
  (_dup_override, one blocking dialog for every fuzzy match, no tiers). They now build
  the tiered flow: CONFIRMED / UNCONFIRMED / CONTRADICTED / AMBIGUOUS_ALIAS / SUPERSEDED.
- Prompt 4 builds the evidence quorum: tax-ID typo, GST no, email domain, postal code /
  address, contact person and phone, with 2+ distinct field groups required. Tests cover
  the new variants 3f, 3g, 3h, both ambiguous-alias fixtures ("abc" and "which NUHS"),
  the quorum rules and the evidence-disclosure rule.
- Prompt 2 seeds the new optional customer fields (Address, ZipCode, CntctPrsn, Phone1,
  U_GSTRegNo) and writes data/dedup_labelled_pairs.json.
- NEW PROMPT 4B: dedup benchmark (precision / recall) for the Executive Summary.
- Prompt 1 (config lint) also checks the corroboration signals.
- Prompts 7A, 7B, 7C and 8 updated to the tier-driven duplicate flow.
- Every prompt still attaches the spec; filename references now point at the v3 spec.

--------------------------------------------------------------------------------
WHAT CHANGED IN v2
--------------------------------------------------------------------------------
- Spec filename fixed (v1 referenced a file that did not exist).
- New prompts for engine_security.py (role switch + field-level security) and
  m365_integration.py (v1 never produced it although the spec required it).
- Abbreviation resolver (NUHS, SMU Solutions, Nat. Uni. Hospital) is part of the
  dedup prompt and its tests.
- Prompts say "read from config" instead of repeating literals (regex, 0.75,
  $50k), which contradicted the zero-hardcoding rule.
- config_rules.json is COPIED from the spec, not regenerated by an LLM. The LLM
  only lints it.
- Mock data comes from a seeded generator script, not hand-written numbers.
- One file per prompt, each followed by tests you run and paste back.
- app.py is split into a shell plus tab modules (the old single app.py would not
  fit one response).
- Added acceptance tests, deployment, deliverables and a bug-fix template.

   match those names and signatures.
